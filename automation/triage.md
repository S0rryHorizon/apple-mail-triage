# Background triage

This prompt applies only when a dispatcher supplies a run_id. Manual skill use and later user candidate confirmation in this weekly task use the current installed skill normally.

1. Call runtime.py with `{"action":"triage.begin","run_id":"<supplied ID>"}`. It registers this task and claims the run. If `should_run` is false, stop; do not repeat scanning.
2. Execute the current installed `$email-triage`, routing every MailBridge request through runtime.py `bridge.call`, for example `{"action":"bridge.call","run_id":"...","request":{"action":"message.scan","limit":200,"previewCharacters":800}}`. Read the MailBridge data inside `bridge`. The helper owns command execution, exit/JSON classification, frozen pagination and failure registration; do not invoke MailBridge directly during this run. Finish pagination, prepare the report, then submit `state.record` through the same entry point.
3. A successful `state.record` automatically sets `run_phase` to `recorded` or `partial` from the actual `deferredBodyCount`. No separate `triage.recorded`/`triage.partial` call is needed. Deliver the report; for `partial`, include what remains unread and do not send the all-complete/empty receipt. A recorded phase alone does not prove report delivery.
4. On `outcome: failed`, the helper has already closed the run as `failed` or `blocked` and returned `recovery`. Follow [failure.md](failure.md) using that result. Correct a request-validation error in place through `bridge.call`; successful continuation leaves `blocked`. On `outcome: unknown`, the helper has closed the run as `unknown`: report it and do not replay it. `outcome: not_run` means the helper did not call MailBridge; obey its reason.

The helper returns a complete JSON envelope even for a handled bridge failure; outer `ok` only means the helper handled the request. Use `outcome` and `run_phase`. If the command yields a live session, collect that same session until it exits. The helper allows 90 seconds for one invocation, never retries it, and stores no mail content or raw error output. A missing or contradictory write receipt is `unknown`, so it cannot cause an automatic duplicate write.

The dispatcher already selects this role's configured model. Do not spawn a substitute model task or perform flags. Do not act on historical prompts that demand old flag checks, special receipts, or a separate confirmation task.
