# Apple Mail Triage 中文使用说明

Apple Mail Triage 是一个运行在本机的 Apple“邮件”整理工具。它由 MailBridge 和 Codex `email-triage` skill 组成：MailBridge 只提供读取、脱敏和本地状态接口；Codex 负责生成中文摘要、风险核查以及待办/日程候选。

## 1. 使用前须知

- 需要 macOS 14 或更高版本。
- 邮箱账号需要先添加到 Apple“邮件”并保持启用。
- 自动整理需要 Codex 桌面 app。
- 本地定时任务运行时，Mac 需要开机且 Codex 可用；错过后可根据最后成功游标追赶。
- 工具没有发送、移动、归档、删除、标垃圾或修改已读状态的接口。
- 发布版没有 Apple Developer ID 公证。请验证校验值，不要全局关闭 Gatekeeper。

## 2. 下载

打开 [GitHub Releases](https://github.com/S0rryHorizon/apple-mail-triage/releases/latest)。

点击 Apple 菜单中的“关于本机”查看芯片：

- Apple M 系列芯片：下载 `Apple-Mail-Triage-版本-macOS-arm64.zip`。
- Intel 芯片：下载 `Apple-Mail-Triage-版本-macOS-x86_64.zip`。

同名 `.sha256` 是校验文件。在下载目录执行：

```sh
shasum -a 256 Apple-Mail-Triage-*.zip
cat Apple-Mail-Triage-*.zip.sha256
```

两行开头的校验值必须一致。

## 3. 安装 Release 版本

双击 ZIP 解压，打开 Terminal，输入 `cd `（末尾保留一个空格），把解压后的文件夹拖入 Terminal，然后回车。执行：

```sh
./install.sh
```

它只会复制：

- `MailBridge.app` 到 `$HOME/Applications/MailBridge.app`；
- `email-triage` 到 `${CODEX_HOME:-$HOME/.codex}/skills/email-triage`。

如果 macOS 阻止运行，请打开“系统设置 → 隐私与安全性”，确认被阻止的对象确实是 MailBridge，再选择“仍要打开”。不要关闭系统的全局安全检查。

## 4. 从源码安装

需要 Xcode Command Line Tools。执行：

```sh
git clone https://github.com/S0rryHorizon/apple-mail-triage.git
cd apple-mail-triage
./scripts/install.sh
```

源码安装会在本机编译与当前处理器匹配的版本。

## 5. 授予 Apple“邮件”权限

确保 Apple“邮件”已经启动，然后执行：

```sh
BRIDGE="$HOME/Applications/MailBridge.app/Contents/MacOS/MailBridge"
printf '%s' '{"action":"setup"}' | "$BRIDGE"
```

macOS 弹出自动化权限时，允许 MailBridge 控制“邮件”。正常返回会包含 `"ok": true` 和已启用账户列表。

若没有弹窗或曾经拒绝，请到“系统设置 → 隐私与安全性 → 自动化”检查 MailBridge 对“邮件”的权限。

## 6. 只读测试

先检查状态：

```sh
printf '%s' '{"action":"status"}' | "$BRIDGE"
printf '%s' '{"action":"state.status"}' | "$BRIDGE"
```

再执行一次只读扫描：

```sh
printf '%s' '{"action":"message.scan","limit":50,"previewCharacters":800}' | "$BRIDGE"
```

第一次默认检查最近 24 小时。之后使用账户游标和 15 分钟重叠窗口，避免延迟同步造成漏件。此步骤不会改变邮件。

## 7. 整理邮件和确认候选

在 Codex 中输入：`使用 $email-triage 整理我的 Apple 邮件。`

重要邮件会给出具体事项、安排和截止日；无须关注时统一回复“本次整理完成，暂无需要关注的新内容。”报告显示在任务里，不另存本地 Markdown。

日程和提醒事项先登记为候选。可以直接在原任务说“把实验报告截止日加入提醒事项”，无需复制编号或另开任务。系统预览你确认的项目后保存；只有选择含糊、缺少日期、重复或时间冲突时才追问。

## 8. 每天自动整理

源码项目中的 `automation/weekly-dispatcher.md` 描述安装流程。推荐每天新加坡时间 08:00、20:00，把结果放进对应周任务：

```text
邮箱整理｜2026-W39｜09.21–09.27
```

当前周和上周保留，更早的受管周任务自动归档。手动任务不在自动清理范围。新周任务和修复任务均从隐藏的空白模板继承邮箱权限，模板平时保持归档。后台普通创建曾回退到受限权限，因此不再使用该路径。

后台整理和分发使用 `gpt-6-luna / max`，修复使用 `gpt-6-astra / medium`，统一在 `automation/settings.json` 修改。分发模型变更还需通过 Codex 自动化工具同步；手动调用 skill 沿用当前任务的模型。

明确返回的技术故障会启动一个独立修复任务，可修复项目代码和专属配置、备份后重装桥接器。最多重跑一次；确认状态保存和实际报告输出后，才归档旧故障任务。仍失败就保留现场并通知你。系统权限、全局设置、账户登录由你决定。不接管完全卡死、没有返回结果的调用。

## 9. 旗标和本地状态

旗标功能已删除：不预览、提交或回滚旗标，也没有开启门槛和影子次数。邮件上已有的旗标保持原样。

状态位于 `$HOME/Library/Application Support/MailTriage/state.sqlite`，保存游标、去重指纹、分类、候选和明确规则，不保存完整正文或附件。升级保留已有数据；旧旗标审计表仅作为历史数据留存。

请勿把状态数据库、自动化记录、Codex 邮箱报告或真实邮件样本上传到 GitHub。

## 10. 卸载和常见问题

先关闭相关自动化，再删除 `~/Applications/MailBridge.app` 和 `${CODEX_HOME:-$HOME/.codex}/skills/email-triage`。如需清除游标、候选和规则，再单独删除 MailTriage 状态目录；这会使下次扫描按首次运行处理。

- **没有权限**：检查系统设置中的自动化权限。重装或 bundle identifier 改变后可能需要重新授权。
- **找不到 skill**：确认技能安装目录存在，必要时重新打开 Codex。
- **没有准时运行**：本地调度依赖 Mac 开机、Codex 可用和项目路径存在；下次运行从最后成功游标追赶。
- **自动回复或删除**：不支持。项目不提供邮件修改接口。
- **Windows**：不支持；Intel 发布包也只适用于 macOS。
- **报告问题**：使用合成示例，不上传真实正文、地址、Message-ID、验证码、令牌、数据库或附件。安全漏洞请私下联系维护者。
