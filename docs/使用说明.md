# Apple Mail Triage 中文使用说明

Apple Mail Triage 是一个运行在本机的 Apple“邮件”整理工具。它由 MailBridge 和 Codex `email-triage` skill 组成：MailBridge 只提供受限的读取、脱敏、状态和可回滚旗标接口；Codex 负责生成中文摘要、风险核查以及待办/日程候选。

## 1. 使用前须知

- 需要 macOS 14 或更高版本。
- 邮箱账号需要先添加到 Apple“邮件”并保持启用。
- 自动整理需要 Codex 桌面 app。
- 本地定时任务运行时，Mac 需要开机且 Codex 可用；错过后可根据最后成功游标追赶。
- 工具没有发送、移动、归档、删除、标垃圾或修改已读状态的接口。
- 发布版没有 Apple Developer ID 公证。请验证校验值，不要全局关闭 Gatekeeper。

## 2. 下载

打开 [GitHub Releases](https://github.com/S0rryHorizon/apple-mail-triage/releases/latest)。

点击 Apple 菜单中的“关于本机”查看芯片：

- Apple M 系列芯片：下载 `Apple-Mail-Triage-版本-macOS-arm64.zip`。
- Intel 芯片：下载 `Apple-Mail-Triage-版本-macOS-x86_64.zip`。

同名 `.sha256` 是校验文件。在下载目录执行：

```sh
shasum -a 256 Apple-Mail-Triage-*.zip
cat Apple-Mail-Triage-*.zip.sha256
```

两行开头的校验值必须一致。

## 3. 安装 Release 版本

双击 ZIP 解压，打开 Terminal，输入 `cd `（末尾保留一个空格），把解压后的文件夹拖入 Terminal，然后回车。执行：

```sh
./install.sh
```

它只会复制：

- `MailBridge.app` 到 `$HOME/Applications/MailBridge.app`；
- `email-triage` 到 `${CODEX_HOME:-$HOME/.codex}/skills/email-triage`。

如果 macOS 阻止运行，请打开“系统设置 → 隐私与安全性”，确认被阻止的对象确实是 MailBridge，再选择“仍要打开”。不要关闭系统的全局安全检查。

## 4. 从源码安装

需要 Xcode Command Line Tools。执行：

```sh
git clone https://github.com/S0rryHorizon/apple-mail-triage.git
cd apple-mail-triage
./scripts/install.sh
```

源码安装会在本机编译与当前处理器匹配的版本。

## 5. 授予 Apple“邮件”权限

确保 Apple“邮件”已经启动，然后执行：

```sh
BRIDGE="$HOME/Applications/MailBridge.app/Contents/MacOS/MailBridge"
printf '%s' '{"action":"setup"}' | "$BRIDGE"
```

macOS 弹出自动化权限时，允许 MailBridge 控制“邮件”。正常返回会包含 `"ok": true` 和已启用账户列表。

若没有弹窗或曾经拒绝，请到“系统设置 → 隐私与安全性 → 自动化”检查 MailBridge 对“邮件”的权限。

## 6. 只读测试

先检查状态：

```sh
printf '%s' '{"action":"status"}' | "$BRIDGE"
printf '%s' '{"action":"state.status"}' | "$BRIDGE"
```

再执行一次只读扫描：

```sh
printf '%s' '{"action":"message.scan","limit":50,"previewCharacters":800}' | "$BRIDGE"
```

第一次默认检查最近 24 小时。之后使用账户游标和 15 分钟重叠窗口，避免延迟同步造成漏件。此步骤不会改变邮件。

## 7. 在 Codex 中使用

1. 把克隆或下载后的项目文件夹添加为 Codex 本地项目。
2. 安装完成后重新打开 Codex，使 `$email-triage` 可被发现。
3. 在该项目中输入：`使用 $email-triage 整理我的 Apple 邮件，先只读预演，不提交旗标。`
4. 检查报告中的高风险、候选、摘要和统计是否准确。

报告不会另存为本地 Markdown；它只显示在对应的 Codex 任务中。

## 8. 设置每天自动整理

推荐每天按新加坡时间 08:00、20:00 运行，并把结果放进每周固定任务，例如：

```text
邮箱整理｜2026-W35｜08.24–08.30
```

最方便的方法是在该项目中对 Codex 说：

```text
请读取 automation/weekly-dispatcher.md，为当前项目创建每天新加坡时间 08:00、20:00 的邮件整理任务。使用轻量模型；先保持影子模式，只预览旗标。
```

分发器会保留本周和上周两个受管周报，归档更早的受管周报；手动讨论、候选确认和排错任务不会被自动归档。任务投递失败时，临时分发器会保留并显示错误。

## 9. 旗标与日历边界

新安装默认关闭真实旗标。影子模式只说明哪些邮件“拟加”红旗或橙旗。确认多次报告准确后，才执行：

```sh
./scripts/enable-flagging.sh
```

这只是开启本地状态门；每次真实提交仍需明确确认，已有旗标不会被覆盖，并会返回可回滚的批次 ID。

邮件产生的日程或提醒事项默认只是候选。只有用户明确确认候选 ID 后，`apple-calendar-assistant` 才会调用 CalendarBridge 预览；重复、冲突或缺少日期时必须停止询问。

## 10. 本地数据与隐私

状态数据库位于：

```text
$HOME/Library/Application Support/MailTriage/state.sqlite
```

其中只保存游标、指纹、分类、候选、明确规则和旗标审计，不保存完整正文、附件、验证码或认证令牌。临时附件只能按白名单和大小限制导出，并应在读取后立即清理。

请勿把状态数据库、automation memory、Codex 邮箱报告或真实邮件样本提交到 GitHub。

## 11. 卸载

先关闭相关 Codex 自动化，再删除：

```text
$HOME/Applications/MailBridge.app
${CODEX_HOME:-$HOME/.codex}/skills/email-triage
```

如果还要清除游标、候选、规则与审计记录，再单独删除：

```text
$HOME/Library/Application Support/MailTriage
```

删除状态目录会让下次扫描重新按首次运行处理。请先确认不再需要待处理候选和回滚记录。

## 12. 常见问题

### 提示没有权限

检查“系统设置 → 隐私与安全性 → 自动化”，并确认 Apple“邮件”正在运行。重新安装或 bundle identifier 改变后可能需要再次授权。

### 找不到 `$email-triage`

确认目录存在于 `$HOME/.codex/skills/email-triage`，然后重新打开 Codex。

### 定时任务没有准时运行

本地任务依赖 Mac 开机、Codex 可用和项目路径存在。恢复后应从最后成功游标追赶，并在报告中显示计划时间、实际时间和延迟。

### 可以自动回复或删除邮件吗

不可以。项目刻意不提供这些接口，以减少提示注入或误操作造成的风险。

### 可以在 Windows 上运行吗

不可以。`x86_64` Release 是给 Intel 芯片的旧款 Mac，不是 Windows 版本。本项目依赖 Apple“邮件”、AppleScript/AppKit 和 macOS 自动化权限，因此只支持 macOS。

### 如何报告问题

可以提交 GitHub Issue，但只能使用合成示例。不要上传真实正文、地址、Message-ID、验证码、令牌、数据库、附件或自动化 memory。安全漏洞请私下联系仓库所有者。
